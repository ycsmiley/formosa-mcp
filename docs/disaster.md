# 停班停課與災防告警（disaster 工具集，預設關閉；尚未部署）

stdio 的 `disaster` 工具集須以 `--toolsets=disaster` 或 `--toolsets=invoice,stock,garbage,outage,disaster` 明確啟用。

- `work_school_closure {city}`：查縣市今天／明天的天然災害停班停課官方原文；`disaster` 工具集，需以 `--toolsets` 明確啟用。
- `disaster_alerts {city}`：查縣市生效中的 NCDR 告警（含地震、停水），依嚴重度排序，最多顯示 20 則。新竹／嘉義未指定市縣時兩者都列出。

## 啟用方式

`disaster` 在所有環境預設關閉，需分別明確啟用：

- stdio：使用 `--toolsets=disaster`，或在 `--toolsets` 清單中加入 `disaster`。
- Worker：在 wrangler 的 `vars` 或 dashboard 設定 `DISASTER_ENABLED = "true"`（必須完全等於小寫 `true`）才會註冊工具；要啟用收集，須在同一次 opt-in 變更中，將 `"5,15,25,35,45,55 * * * *"` 加在 `triggers.crons` 原有四條之後，並將 [test/worker/disaster.test.ts](../test/worker/disaster.test.ts) 的 `keeps checked-in wrangler.jsonc at the default four crons` 測試中的唯一斷言改為預期 `[...Object.keys(cronJobs), disasterCron]`。其他設定測試已接受這兩種配置，不需修改。目前設定僅有 main 的四條 cron，正常部署不新增 cron；旗標未設定或不完全等於小寫 `true` 時，disaster cron 即使觸發也不讀寫 KV、不執行其他 collector。
- GitHub Actions：設定 repository variable `DISASTER_ENABLED=true`；值必須完全等於小寫 `true`。job-level `if` 僅作不區分大小寫的預篩，第一個 `gate` 步驟再以 shell 作區分大小寫的精確檢查；其他值會跳過所有後續步驟及 KV 寫入，若進入 gate 則顯示 notice 並成功結束。排程與手動執行均適用。

Workers Free 每個 **ACCOUNT 共用 5 條 cron triggers**；main 已使用 4 條，啟用 disaster cron 會用掉最後一條，同帳號其他 Worker 不得再使用 cron。

## 收集與資料處理

啟用後，停班停課與告警採雙層收集：Worker 每 10 分鐘 x5（`5,15,25,35,45,55 * * * *`），每輪最多 4 個 CAP，NCDR 請求須在 cron 的 scheduledTime 起 60 秒內、且該排程週期 x7:00 前開始（延遲啟動會扣掉已耗時間）；[GHA collector](../.github/workflows/disaster-collect.yml) 每小時 `20 * * * *`、最多 20 個 CAP。GHA 僅在 Worker 該來源成功、未關閉、有可讀分片、來源更新符合各來源時間限制（DGPA 未滿 90 分鐘；NCDR 不超過 24 小時；均未超前逾 5 分鐘）、成功抓取距今非負且嚴格小於 25 分鐘時跳過。每輪 NCDR JSON／Atom／CAP 請求在前一回應結束後至少等 3.1 秒；延遲 GHA 另避開 x4:30～x7:00。此安排不保證跨程序互斥；共享協調器列為後續工作。兩個 feed 或任一 CAP 要求登入時顯示「尚未支援」，不使用金鑰。

Cloudflare 出口可達性尚待部署驗證；啟用後每小時 GHA 為備援。逐來源按 `sourceUpdatedAt` 新到舊選資料，同時才比較 `lastSuccessAt`；收集時拒絕自身來源版本倒退，對方已有更新版本便跳過發布。NCDR 新鮮度以最近一次非 skipped 抓取成功、所選 `lastSuccessAt` 未滿 90 分鐘為準；feed `updated` 是最新告警時間，安靜期可早於 90 分鐘，只有超過 24 小時、超前逾 5 分鐘或版本倒退才拒用。DGPA 保留頁面更新與成功抓取的 90 分鐘規則。缺少來源時間仍不可用，任一時間超前逾 5 分鐘顯示「資料時間異常」；索引損毀顯示「索引無法解讀」。停班停課引用官方原文，過期時隱藏「照常」、無事件頁面標為歷史資料，頁面日期不同另行提示。

只有資料新鮮、最近一次非 skipped 抓取成功、非空或經雙格式驗證為空、且所有告警範圍完整時，才可說「目前沒有…生效中的告警」。NCDR 沒有明確空清單訊號，也無真實空樣本：JSON 必須有非空 id/title、author.name===NCDR、符合 24 小時／5 分鐘限制的 updated，且缺少/null/[] entry 或全部非 Actual/Cancel 過濾後為零；接著以同一請求節流 helper 取得 Atom，也須符合相同結構／時間／零筆條件，才發布 `[]` 與 `empty:true`。兩格式不同、任一無效或只有單格式時皆視為失敗，保留舊分片。CAP 至少有一個 area，且每個區域都能由 areaDesc 縣市前綴或 Taiwan_Geocode_103 地理碼判定縣市才標為 `complete:true`；縣市取兩者聯集，查詢範圍列出該縣市的 areaDesc（包含地震震度區域），保留上限 200 處／每處 100 字；摘要與舊版缺少標記者不完整，阻止無告警宣稱，並列出可能涵蓋查詢縣市的未確認項目。已知告警仍列出，未生效者顯示「即將生效」與臺北時間。縣轄市／鄉鎮市區可唯一對應縣市時加註轉換，新竹／嘉義歧義維持兩者並列。欄位有長度與清理限制，連結僅允許 NCDR HTTPS 網域，兩工具回應最多 16 KiB UTF-8，截斷後保留來源。

KV 採獨立索引 `disaster:index:{worker|gha}:v1`、不可變分片 `disaster:v1:{dgpa|ncdr}:{sha12}`（SHA-256 前 12 碼）；分片 TTL 8 天，超過 3 天才搭配已需寫入的索引續期，索引最後發布。兩 writer 僅狀態變更或 55 分鐘心跳才寫索引；GHA 全部跳過且無變更時零寫入。Worker token bucket 每小時 3、burst 9，保守上限 81 次／24h；GHA 每小時 1.5、burst 6，上限 42 次／24h，額度不足優先 DGPA。KV Free **每帳號共用 1,000 次／日**；明確啟用 disaster 後，全部排程最壞估算約 700（703）次／日，嚴格 ≤700 的最小後續調整與完整逐項計算見 [KV 寫入預算](kv-budget.md)。Free 五條 cron 上限亦為每帳號；目前配置四條，明確加入 disaster cron 後才全數用完。

本機執行 `npm run collect:disaster -- --out /tmp/formosa-disaster`，再設 `FORMOSA_DISASTER_DIR=/tmp/formosa-disaster` 供 stdio 讀取。未設時 Node 按查詢來源獨立執行共用 collector、最多 6 個 CAP，每次請求逾時 12 秒，成功快取 10 分鐘、失敗快取 2 分鐘並保留失敗原因及先前成功資料；停班停課查詢不等候 NCDR，不採 GHA 的 peer skip 或 quiet window。更新 publisher 後由 `npm run build:collectors` 重建 `scripts/dist/`，workflow 直接執行已提交的 bundle。

## English

The `disaster` toolset is off by default everywhere and is not deployed. For stdio, enable it explicitly with `--toolsets=disaster` or `--toolsets=invoice,stock,garbage,outage,disaster`. The Worker requires `DISASTER_ENABLED = "true"` in wrangler `vars` or the dashboard, with the value exactly lowercase `true`, to register the tools. To enable scheduled collection, append `"5,15,25,35,45,55 * * * *"` after the existing four entries in `triggers.crons` AND update the single assertion in `keeps checked-in wrangler.jsonc at the default four crons` in [test/worker/disaster.test.ts](../test/worker/disaster.test.ts) to expect `[...Object.keys(cronJobs), disasterCron]`, in the same opt-in change. The other config tests already accept both configurations. The checked-in config keeps four crons, so a normal deploy adds no cron. GHA requires repository variable `DISASTER_ENABLED=true`, also exactly lowercase `true`. Its job-level `if` is a case-insensitive pre-filter; the first `gate` step enforces the exact value with a case-sensitive shell check. Other values skip every subsequent step and all KV writes; if the gate runs, it prints a notice and exits successfully. This applies to both scheduled and manual runs. Workers Free allows five cron triggers per account. Main already uses four; enabling disaster takes the final slot, so no other Worker on the account may use crons.

- `work_school_closure {city}`: official DGPA work/school closure statements for today and tomorrow; `disaster` toolset; enable explicitly with `--toolsets`.
- `disaster_alerts {city}`: active NCDR alerts, including earthquakes and water outages, sorted by severity; up to 20 shown. Ambiguous Hsinchu/Chiayi names return both city and county. All replies use Traditional Chinese and official links.

When explicitly enabled, disaster collection has two layers: the Worker runs every ten minutes at x5 (`5,15,25,35,45,55 * * * *`), starts NCDR requests within 60 seconds of the cron's scheduledTime and before that scheduled cycle's x7:00 guard (startup delays consume the budget), and fetches at most four CAPs. The [hourly GHA collector](../.github/workflows/disaster-collect.yml) runs at `20 * * * *` with at most 20 CAPs. GHA skips a source only when the Worker is successful, open, has an existing shard, has source data within the source-specific limit (DGPA under 90 minutes, NCDR at most 24 hours, neither more than five minutes ahead), and its last success is nonnegative and strictly under 25 minutes old. Every JSON/Atom/CAP request waits at least 3.1 seconds after the preceding response; delayed GHA runs also avoid x4:30–x7:00. This does not serialize independent runs: a shared coordinator is a follow-up. Login requirements from both feeds or any CAP produce the unsupported-access notice; no NCDR key is used.

Cloudflare egress reachability awaits deployment verification; hourly GHA provides fallback when enabled. Readers rank source revisions by `sourceUpdatedAt`, breaking ties with `lastSuccessAt`. Collectors reject regressions against their own last-good revision and skip publication when a peer has newer evidence. NCDR freshness requires a successful latest non-skipped attempt and chosen lastSuccessAt strictly under 90 minutes old. Feed updated is the newest alert time and can legitimately be hours old during quiet periods; reject it only above 24 hours old, more than five minutes ahead, or regressing against last-good evidence. DGPA retains its 90-minute page/fetch rule. Missing source timestamps remain unusable; either timestamp more than five minutes ahead produces a clock-anomaly notice. Corrupt indexes report an unreadable-index reason. Closure output quotes official statements, withholds stale “照常”, marks stale no-event pages as historical, and flags different page dates.

An active-absence claim requires fresh evidence, a successful latest non-skipped attempt, nonempty or verified-empty data, and complete geographic coverage. NCDR supplies no explicit empty signal and no real empty sample exists. A zero-usable-entry JSON feed (missing/null/[] entries or all non-Actual/Cancel) must have nonblank id/title, author.name===NCDR and updated within the 24-hour/five-minute limits; the next Atom request, through the same pacing helper, must independently meet those structural/time checks and also yield zero usable entries. Only then publish `[]` with `empty:true`. Disagreement, either invalid format, or only one available format fails and retains last-good data. CAP geography is `complete:true` only with at least one area and every area mapping to a county through its areaDesc prefix or Taiwan_Geocode_103 numeric prefix. Each area uses the union of both; county-specific output includes matching intensity descriptions, with 200 stored areas of up to 100 characters each. Summaries and legacy items without the marker remain incomplete and block absence claims; uncertain items are shown for other counties too. Known alerts remain visible after fetch failures. Upcoming alerts include their effective time in Taipei. Unambiguous township/county-city input maps to its county with an explanation; Hsinchu/Chiayi ambiguity remains. Display fields are sanitized and bounded, emitted links use only NCDR HTTPS URLs, and each response is capped at 16 KiB UTF-8 with attribution retained.

Independent indexes use `disaster:index:{worker|gha}:v1`; immutable shards use `disaster:v1:{dgpa|ncdr}:{sha12}` (first 12 SHA-256 hex characters), eight-day TTL and renewal after three days only alongside an already-due index publication. Indexes follow shards. Both writers publish on state changes or a 55-minute heartbeat; unchanged GHA runs skipping every source write nothing. Worker bucket: 3 tokens/hour, burst 9, at most 81 writes/24h; GHA: 1.5/hour, burst 6, at most 42 writes/24h. Under pressure DGPA takes priority. The Free **1,000 KV writes/day are account-wide**; with disaster explicitly enabled, the combined scheduled worst estimate is approximately 700/day (703); an explicit rail call cap would reduce it to 699. See the [complete KV budget and smallest proposed follow-up](kv-budget.md), including concurrency/persistence assumptions. The five-cron Free limit is also account-wide; this Worker configures four by default and uses all five only after opting into the disaster cron.

For local snapshots run `npm run collect:disaster -- --out /tmp/formosa-disaster`, then set `FORMOSA_DISASTER_DIR=/tmp/formosa-disaster`. Otherwise stdio runs the shared collector independently for each queried source in Node, with up to six CAP fetches, a 12-second request timeout, a ten-minute success cache and a two-minute failure cache retaining the reason and older good data. Closure queries do not wait on NCDR. Local collection uses neither peer skipping nor the GHA quiet window. Regenerate committed publisher bundles with `npm run build:collectors`; the workflow executes the committed bundle.
